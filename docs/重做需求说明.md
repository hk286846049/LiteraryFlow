# LiteraryFlow 重做需求说明

版本：2026-08-24  
来源：基于当前项目源码、Manifest、数据模型、自动化执行逻辑和现有“项目功能分析”文档反向整理。  
用途：作为重做版本的产品需求底稿，不把当前实现方式、Bug 和性能问题作为新版本约束。

## 1. 背景与目标

当前项目已经形成“Android 自动化任务配置器 + 无障碍执行引擎 + OCR/截图辅助 + 悬浮窗运行控制台”的雏形，但实现层面耦合较重、运行链路不稳定、性能开销偏大，适合基于现有功能重新设计和实现。

重做目标：

- 保留现有核心能力：任务配置、动作编排、条件判断、定时/循环调度、悬浮窗控制、OCR/截图取参、导入导出。
- 重建稳定的执行引擎：任务状态、调度、取消、重试、暂停、日志必须可预测。
- 重建数据模型：任务、步骤、动作、条件、运行记录和应用偏好拆分清楚，支持版本迁移。
- 显著提升性能：避免主线程数据库/截图/OCR/轮询阻塞，控制后台 CPU、内存和电量消耗。
- 明确 MVP 范围：把实验页、HTTP、通知联动、网站检测等能力从主线中剥离为后续扩展。

## 2. 产品定位

LiteraryFlow 是一个运行在 Android 设备上的本地自动化工具，用户可为指定应用配置一组自动化任务，由系统通过无障碍能力、屏幕截图、OCR 识别和悬浮窗控制完成自动点击、滑动、输入、返回、打开应用、找字点击和条件分支执行。

主要使用场景：

- 为指定 App 配置重复性操作流程。
- 在界面控件无法稳定定位时，通过 OCR 找到文本并点击。
- 通过截图或文本取点辅助用户生成点击、滑动和文本匹配参数。
- 通过每日、每周、循环或指定次数方式运行自动化任务。
- 通过悬浮窗在目标 App 上方手动启停、重跑和查看任务状态。

## 3. 用户与使用前提

### 3.1 用户角色

| 角色 | 目标 |
| --- | --- |
| 普通用户 | 选择 App，配置任务，手动或定时运行 |
| 高级用户 | 配置条件分支、子任务、OCR 匹配、任务导入导出 |
| 开发/调试用户 | 查看运行日志、OCR 结果、截图取点和实验能力 |

### 3.2 运行权限

| 权限/能力 | 使用场景 | 需求说明 |
| --- | --- | --- |
| 无障碍服务 | 点击、滑动、输入、返回、节点文本识别、前台 App 判断 | 必须提供清晰引导和状态检测 |
| 悬浮窗权限 | 主控悬浮窗、取点悬浮层、OCR 标注层 | 只在用户启用相关功能时申请 |
| 录屏/MediaProjection | 截图、OCR、截图取点 | 每次授权状态需可感知，失效后重新引导 |
| 使用情况访问 | 判断目标 App 是否在前台 | 若无法授权，应降级为手动确认或跳过前台判断 |
| 通知监听 | 通知触发任务 | 作为 P2 扩展，不进入 MVP 主链路 |
| 文件访问/SAF | JSON 导入导出 | 使用系统文件选择器，避免依赖高风险全盘文件权限 |
| 快捷设置 Tile | 快速打开悬浮窗或 OCR 功能 | 作为便捷入口，不替代 App 内主流程 |

## 4. 功能范围分级

| 优先级 | 范围 |
| --- | --- |
| MVP | 权限引导、任务列表、任务编辑、动作编辑、条件编辑、Room 持久化、手动运行、每日/每周/循环调度、主控悬浮窗、无障碍动作、OCR 找字点击、截图/文本取点、导入导出、基础日志 |
| P1 | 运行记录、失败重试策略、任务模板、任务复制、批量启停、配置校验增强、OCR 缓存、横竖屏适配增强、导入冲突处理 |
| P2 | 通知触发、本地 HTTP 触发、网站检测、云同步、多人共享、实验页整合、复杂流程图编排 |

## 5. 核心业务流程

### 5.1 首次使用流程

1. 用户打开 App。
2. App 展示核心功能入口和权限状态。
3. 用户按需开启无障碍服务、悬浮窗权限、录屏权限和使用情况访问权限。
4. 用户进入任务列表。
5. 用户选择目标应用并新建任务。
6. 用户配置动作、条件和调度规则。
7. 用户保存任务。
8. 用户通过任务列表或悬浮窗运行任务。
9. 系统展示运行状态、进度、结果和错误原因。

### 5.2 自动化任务运行流程

1. 任务进入运行队列。
2. 执行引擎检查任务是否启用、权限是否满足、当前时间是否允许运行。
3. 若任务要求目标 App 在前台，系统检查前台 App。
4. 若允许自动拉起目标 App，则自动打开目标 App；否则本次运行失败并记录原因。
5. 执行引擎按顺序执行步骤。
6. 普通动作直接执行；条件步骤先判断，再执行成立或不成立分支。
7. 每个步骤结束后按配置等待。
8. 单轮结束后更新执行次数、运行记录和悬浮窗状态。
9. 达到次数上限或被用户停止时，任务进入完成/停止状态。

## 6. 功能需求

### FR-001 权限与首页

首页需要作为“权限状态 + 功能入口”的统一入口。

需求：

- 展示无障碍、悬浮窗、录屏、使用情况访问等关键能力的可用状态。
- 提供自动化任务列表入口。
- 提供录屏开启/停止入口。
- 提供主控悬浮窗开启/关闭入口。
- 权限未满足时给出明确原因和跳转入口。
- 不在启动时一次性申请所有权限，按功能需要分阶段申请。
- 录屏权限失效、无障碍服务被系统关闭、悬浮窗被拒绝时，必须给出可恢复提示。

验收标准：

- 用户能在 30 秒内看懂当前缺少哪个权限。
- 任一关键权限缺失时，运行任务不会崩溃，而是失败并记录原因。

### FR-002 应用选择与应用偏好

用户需要选择目标 App 作为任务运行对象，也需要为部分 App 标记方向和收藏状态。

需求：

- 读取设备已安装且可启动的应用。
- 展示应用名称、包名和图标。
- 支持关键词搜索。
- 支持收藏/取消收藏。
- 支持标记横屏、竖屏或自动识别。
- 支持选择应用后回填到任务或动作配置页。
- 支持打开应用动作选择目标 App。

数据项：

| 字段 | 说明 |
| --- | --- |
| appName | 应用名称 |
| packageName | 包名 |
| isFavorite | 是否收藏 |
| orientation | portrait / landscape / auto |
| lastUsedAt | 最近使用时间 |

### FR-003 任务列表

任务列表是任务资产管理中心。

需求：

- 展示全部任务。
- 支持按目标 App 分组。
- 支持新增、编辑、删除任务。
- 支持启用/停用任务。
- 支持手动运行单个任务。
- 支持导入 JSON 任务。
- 支持导出 JSON 任务。
- 支持显示任务的调度类型、目标 App、今日已运行次数、总次数、最近运行结果。
- 支持任务列表为空、导入失败、数据库读取失败等空/错状态。

验收标准：

- 100 个任务内列表打开和分组切换应无明显卡顿。
- 删除任务必须二次确认。
- 导入任务必须先校验格式，不允许坏数据直接写入数据库。

### FR-004 任务创建与编辑

用户需要配置一个完整自动化任务。

任务级配置项：

| 配置项 | 说明 |
| --- | --- |
| 任务名称 | 必填，建议同一设备内唯一 |
| 目标应用 | 必填，保存 appName 和 packageName |
| 是否自动打开目标应用 | 目标应用不在前台时是否自动拉起 |
| 调度类型 | 指定次数、每日、每周、无限循环 |
| 每日时间范围 | 起始时间和结束时间 |
| 每周执行日 | 周一至周日多选 |
| 执行次数 | 正整数；无限循环用独立类型表达，不用特殊字符串入库 |
| 步骤间隔 | 默认动作间隔，可被单动作覆盖 |
| 动作步骤列表 | 串行动作和条件步骤 |
| 监听规则列表 | MVP 可保存但不默认运行；P1/P2 再闭环 |

校验规则：

- 任务名称不能为空。
- 目标应用不能为空。
- 每周任务必须至少选择一天。
- 时间范围必须合法；跨天规则需要明确定义。
- 执行次数、等待时间、扫描时长必须是可解析数字，并有上限。
- 子任务引用不能形成无限递归。

### FR-005 动作编排

动作是任务执行的最小单元。重做版本应把动作定义为稳定枚举和参数对象。

当前已实现动作需要保留：

| 动作 | 参数 | 说明 |
| --- | --- | --- |
| 点击坐标 | x、y、重复次数、等待时间 | 通过无障碍手势点击 |
| 点击文字 | 文本、匹配方式、识别来源、查找超时 | 可基于节点或 OCR 找字后点击 |
| 左右长滑 | 起点 x/y、最小/最大边界、持续时间 | 水平方向连续/长距离滑动 |
| 上下长滑 | 起点 x/y、最小/最大边界、持续时间 | 垂直方向连续/长距离滑动 |
| 左滑 | 固定或可配置起止坐标 | 快捷滑动动作 |
| 右滑 | 固定或可配置起止坐标 | 快捷滑动动作 |
| 上滑 | 固定或可配置起止坐标 | 快捷滑动动作 |
| 下滑 | 固定或可配置起止坐标 | 快捷滑动动作 |
| 输入文字 | 输入内容、等待时间 | 向当前焦点输入文本 |
| 返回 | 无或返回方式 | 执行系统返回 |
| 打开应用 | appName、packageName | 拉起指定应用 |
| 长按 | x、y、持续时间 | 长按指定坐标 |
| 执行子任务 | 子任务引用 | 执行另一组步骤 |

通用动作参数：

- 动作名称或展示描述。
- 重复次数。
- 动作后等待时间。
- 是否失败后继续。
- 失败重试次数。
- 超时时间。

验收标准：

- 动作配置页能新增、编辑、插入、删除和重新排序动作。
- 所有动作保存后再次打开必须完整回填。
- 动作执行失败必须返回明确错误码和错误信息。

### FR-006 文本匹配与 OCR 来源

文本相关动作和条件必须支持多种匹配方式和识别来源。

匹配方式：

| 匹配方式 | 说明 |
| --- | --- |
| 完全匹配 | 文本完全一致 |
| 模糊匹配 | 目标文本被包含或相似匹配 |
| 多词模糊匹配 | 多个关键词任一或全部命中，规则需配置明确 |

识别来源：

| 来源 | 说明 |
| --- | --- |
| 无障碍节点 | 从当前界面节点文本中查找 |
| OCR 截图 | 截取屏幕并识别文字块 |

需求：

- 文字点击需要返回命中的文本、位置和来源。
- OCR 结果应包含文本、边界框、置信度、截图时间。
- OCR 轮询必须有节流和超时。
- OCR 失败、截图失败、权限失效时不能无限等待。
- 横屏 App 的坐标和截图方向必须统一换算。

### FR-007 条件判断

条件用于在任务中实现分支。

当前需要保留的条件类型：

| 条件 | 参数 | 说明 |
| --- | --- | --- |
| 文本出现 | 文本、匹配方式、识别来源、扫描时长 | 在限定时间内寻找文字 |
| 时间范围 | 起止时间 | 判断当前时间是否处于范围内 |

条件结果：

- 条件成立后可执行一个动作。
- 条件成立后可执行一组子任务步骤。
- 条件不成立后可执行一个动作。
- 条件不成立后可执行一组子任务步骤。

验收标准：

- 条件判断必须有确定的结束状态：成立、不成立、超时、异常。
- 条件嵌套或子任务执行时，取消信号必须能及时中断。
- 条件分支中失败的动作必须记录到父任务运行记录。

### FR-008 监听规则

监听规则在当前项目中已经有数据结构和配置入口，但执行闭环不完整。

MVP 需求：

- 可在任务编辑页保留监听规则配置入口，或暂时隐藏。
- 如保留入口，必须明确标记为实验功能。
- 监听规则数据不得影响主任务稳定执行。

P1/P2 需求：

- 支持在任务运行期间持续监听文本或状态。
- 命中后触发指定动作或任务。
- 支持监听生命周期：启动、暂停、停止、超时。
- 支持监听频率限制，避免持续 OCR 造成性能问题。

### FR-009 调度与运行引擎

执行引擎是重做重点，必须从 UI 和悬浮窗中解耦。

调度类型：

| 类型 | 说明 |
| --- | --- |
| 指定次数 | 用户手动或触发后执行 N 次 |
| 每日 | 每天在指定时间/时间范围内执行 |
| 每周 | 指定星期和时间/时间范围执行 |
| 无限循环 | 按间隔持续执行，直到用户停止 |

运行状态：

| 状态 | 说明 |
| --- | --- |
| idle | 未运行 |
| scheduled | 等待调度 |
| running | 执行中 |
| paused | 暂停 |
| stopping | 停止中 |
| success | 完成 |
| failed | 失败 |
| canceled | 用户取消 |

需求：

- 调度器负责“什么时候运行”，执行器负责“如何运行”。
- 同一任务不允许无控制地并发执行。
- 支持取消、暂停、恢复、重跑。
- 支持任务运行记录，不直接用任务配置对象承载临时运行态。
- 今日执行次数必须跨天自动重置。
- 调度持久化需要考虑 App 被杀、设备重启后的恢复策略。
- 运行任务时必须校验目标 App 前台状态和自动拉起策略。

验收标准：

- 用户点击停止后，当前任务应在 1 秒内进入停止流程，最多在当前不可中断动作结束后停止。
- 应用退到后台、悬浮窗关闭、录屏权限失效时，运行状态必须一致。

### FR-010 主控悬浮窗

主控悬浮窗是运行态控制台。

需求：

- 支持折叠/展开。
- 展示任务分类：每日、每周、循环、执行中、已完成。
- 支持按应用分组查看任务。
- 支持启动/停止单个任务。
- 支持重跑任务。
- 支持长按进入任务编辑。
- 展示当前任务名、执行进度、当前次数/总次数。
- 支持暂停当前运行。
- 支持关闭悬浮窗并停止关联的取点/OCR 悬浮服务。

性能要求：

- 悬浮窗刷新由状态流驱动，不允许高频全量轮询数据库。
- 列表数据应增量刷新或按当前分类懒加载。

### FR-011 截图取点与文本取点

辅助配置能力用于降低用户配置成本。

截图取点需求：

- 显示覆盖目标 App 的取点悬浮层。
- 支持用户框选矩形区域。
- 支持回传中心点、边界范围或原始矩形。
- 支持区分点击坐标、长按坐标、滑动区域。
- 支持横竖屏坐标换算。

文本取点需求：

- 扫描当前页面可识别文本。
- 在屏幕上标注文本区域。
- 用户点击文本区域后回传文本内容。
- 可选回传文本中心点。
- 支持节点来源优先、OCR 来源补充。

验收标准：

- 取点结果必须带来源、截图时间、屏幕方向和原始坐标系。
- 回填配置页后保存再打开，值保持一致。

### FR-012 OCR 标注与识别

需求：

- 支持通过录屏截图获取当前屏幕图像。
- 支持中文文字识别。
- 支持展示 OCR 文本块和边界框。
- 支持按匹配规则查找目标文本。
- 支持返回首个命中或按策略选择最佳命中。
- 支持用户查看最近一次 OCR 识别结果。

性能要求：

- OCR 不得在主线程运行。
- 连续 OCR 必须做节流、取消和复用最近帧。
- 同一截图在短时间内多次找字时，应复用识别结果。

### FR-013 导入导出

需求：

- 支持导出全部任务到 JSON。
- 支持从 JSON 导入任务。
- JSON 必须包含 schemaVersion。
- 导入前必须完成格式校验、字段校验和枚举校验。
- 导入时支持冲突策略：跳过、覆盖、复制为新任务。
- 导出文件不得包含设备敏感信息，除非用户明确选择。

建议 JSON 顶层结构：

| 字段 | 说明 |
| --- | --- |
| schemaVersion | 数据格式版本 |
| exportedAt | 导出时间 |
| appVersion | App 版本 |
| tasks | 任务列表 |
| appPreferences | 应用偏好，可选 |

### FR-014 日志与错误反馈

需求：

- 每次任务运行生成运行记录。
- 记录任务开始、步骤开始、步骤结束、条件结果、失败原因、取消原因。
- 错误对用户展示为可理解文本。
- Debug 日志页可作为开发辅助，但不应成为用户定位问题的唯一方式。
- Release 版本不能输出过量敏感日志。

运行记录字段：

| 字段 | 说明 |
| --- | --- |
| runId | 单次运行 ID |
| taskId | 任务 ID |
| startTime/endTime | 开始/结束时间 |
| status | 成功、失败、取消等 |
| currentStepIndex | 失败或停止时的步骤 |
| errorCode/errorMessage | 错误码和错误信息 |
| screenshotRef | 可选，仅调试模式保存 |

## 7. 数据需求

### 7.1 核心实体

建议重做时拆分以下实体：

| 实体 | 说明 |
| --- | --- |
| Task | 任务基础信息和调度配置 |
| Step | 任务中的顺序步骤 |
| Action | 具体动作参数 |
| Condition | 条件判断参数和分支 |
| AppPreference | 应用收藏、方向和最近使用 |
| RunRecord | 单次任务运行结果 |
| StepRecord | 单步骤执行结果 |

### 7.4 数据迁移要求

- 不再把所有复杂结构长期作为无版本 JSON blob 直接塞入单表字段。
- 所有枚举必须有未知值兜底，避免旧数据导致崩溃。
- Room 版本迁移必须覆盖每一个版本跨度。
- 导入 JSON 和数据库 schema 应分别维护版本。
- 保存任务前需要生成可验证的数据快照。

## 8. 非功能需求

### 8.1 性能指标

| 场景 | 目标 |
| --- | --- |
| 冷启动进入首页 | 2 秒内可交互 |
| 打开 100 个任务列表 | 300 ms 内完成首屏数据展示 |
| 切换任务分组 | 200 ms 内完成 |
| 启动单个任务 | 500 ms 内进入 running 或明确失败 |
| 普通无障碍动作派发 | 200 ms 内开始执行 |
| 单次 OCR 识别 | 普通设备目标 1.5 秒内返回，超时可配置 |
| 连续 OCR | 默认最小间隔不低于 500 ms，可按场景调整 |
| 停止任务 | 1 秒内状态响应，当前手势结束后停止 |

### 8.2 稳定性

- 数据库、OCR、截图和包管理查询不得阻塞主线程。
- 服务被系统回收后，UI 状态必须能恢复或明确提示。
- 录屏授权失效、无障碍关闭、悬浮窗权限取消时，任务必须安全停止。
- 执行引擎需要统一取消信号，避免协程泄漏。
- 子任务嵌套需要限制深度并检测循环引用。
- 所有长耗时循环必须可取消、可超时、可记录。

### 8.3 隐私与安全

- 明确告知用户无障碍和录屏能力的用途。
- OCR 截图默认只在内存中处理，不落盘。
- 若开启调试截图保存，必须由用户显式打开。
- 导出数据前提示包含的内容。
- 不自动上传任务、截图、OCR 文本和应用列表。

### 8.4 兼容性

- 当前项目基线为 minSdk 24、targetSdk 35、compileSdk 35，重做版本建议继续以 Android 7.0+ 为最低兼容线。
- 需要兼容 Android 12+ 录屏授权流程和前台服务限制。
- 需要兼容 Android 13+ 通知、前台服务、文件访问策略变化。
- 横屏、竖屏、刘海屏、导航栏、状态栏坐标必须统一处理。

## 9. 当前实现中不应继承的实现假设

这些是重做时需要避免的技术假设，不是功能需求本身：

- 不应依赖硬编码坐标完成通用滑动，快捷滑动也应基于屏幕尺寸计算。
- 不应通过固定中文系统弹窗文本自动点击录屏授权，授权流程应可感知、可失败、可恢复。
- 不应让 UI、悬浮窗和执行引擎共享大量全局可变状态。
- 不应让任务配置对象同时承担运行状态、今日次数和临时 UI 状态。
- 不应高频全量 OCR 或高频数据库刷新。
- 不应把实验页、调试页和正式功能入口混在同一主流程里。
- 不应忽略数据库版本迁移跨度。

## 10. 实验与暂缓功能

以下能力当前项目已有入口、服务或代码骨架，但不建议进入重做 MVP：

| 功能 | 当前状态 | 建议 |

| 通知监听触发 | 有 NotificationListenerService | P2，先定义通知规则模型 |

| OCR 调试页/日志页 | 研发辅助 | 保留为 debug 功能，不进入用户主路径 |

## 11. MVP 验收清单

MVP 完成时至少满足：

- 用户能完成“选择 App → 新建任务 → 添加动作 → 保存 → 运行 → 查看结果”的完整闭环。
- 支持点击坐标、点击文字、滑动、输入文字、返回、打开应用、长按、子任务。
- 支持文本条件和时间条件。
- 支持每日、每周、无限循环、指定次数运行。
- 支持主控悬浮窗启停和展示任务状态。
- 支持 OCR 找字点击和截图/文本取点。
- 支持任务 JSON 导入导出。
- 权限缺失不会导致崩溃。
- 100 个任务、20 步任务、连续运行 30 分钟的场景下无明显卡死和协程/服务泄漏。
- 任务失败时能看到失败步骤和原因。

## 12. 建议重做拆分

推荐按以下模块拆分，避免再次形成大对象和服务耦合：

| 模块 | 职责 |
| --- | --- |
| permission | 权限状态检测、引导、授权结果 |
| app-catalog | 已安装应用、收藏、方向偏好 |
| task-data | Room 实体、DAO、Repository、导入导出 |
| task-editor | 任务、动作、条件编辑 UI |
| scheduler | 每日/每周/循环/次数调度 |
| executor | 动作执行、条件执行、任务状态机 |
| accessibility | 无障碍节点查找、点击、输入、手势 |
| capture-ocr | 录屏、截图、OCR、文本块缓存 |
| overlay | 主控悬浮窗、取点浮层、OCR 标注 |
| logging | 运行记录、错误码、调试日志 |

## 13. 待确认问题

重做前建议优先确认：

- 产品主场景是通用自动化工具，还是偏手游辅助工具？
- 是否允许任务在 App 关闭或设备锁屏后继续调度？
- OCR 是否必须离线本地完成，是否允许引入更重模型？
- JSON 导入导出是否需要兼容当前旧数据？
- 监听规则是否进入首版，还是明确延后？
- 是否需要支持任务模板市场或云同步？
